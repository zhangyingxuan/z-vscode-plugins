# 知识库维护制度

> 最后验证：2026-09-24

本文定义知识库的持续维护规则，确保文档与代码同步演化。

---

## 1. 文档保鲜规则

### 验证日期

每份分类文档头部包含 `> 最后验证：YYYY-MM-DD`。

| 状态 | 条件 | 动作 |
|------|------|------|
| 新鲜 | ≤ 30 天 | 无需动作 |
| 需复查 | 31-90 天 | 下次涉及该领域时优先复查 |
| 可能过期 | > 90 天 | 主动安排复查 |

### 谁负责更新

| 分类 | 责任人 | 复查频率 |
|------|--------|----------|
| 01-需求分析 | 插件作者（需求变更时） | 功能变更后 |
| 02-业务梳理 | 插件作者 | 业务流程/规则变更时 |
| 03-架构设计 | 插件作者 | 架构决策变更时 |
| 04-技术方案 | 对应开发者 | 代码变更后 |
| 05-API文档 | 数据服务开发者 | 接口/数据模型变更后 |
| 06-开发规范 | 插件作者 | 版本/流程变更时 |
| 07-测试用例 | 插件作者 / QA | 功能变更后 |

---

## 2. 分类索引维护规则

每个分类目录下有一个 `_index.md`，AGENTS.md 通过两级路由依赖这些索引。

### 新增文档时
1. 在对应分类目录创建 `.md` 文件，头部带 `> 最后验证：YYYY-MM-DD`
2. 在对应 `_index.md` 的表格中新增一行（触发关键词 + 一句话说明）
3. 更新 `README.md` 中的导航链接

### 索引健康检查
```bash
bash scripts/check-index-coverage.sh
```

## 3. 代码→文档触发规则

| 代码变更 | 必须检查文档 | 检查内容 |
|----------|-------------|----------|
| `src/extension.ts` 命令/定时器/状态栏变更 | `01-需求分析/功能需求清单.md` | 命令表、快捷键、功能验收 |
| `src/extension.ts` 刷新逻辑变更 | `02-业务梳理/业务流程.md` | 刷新机制、交易时段规则 |
| `src/services/stock-data.ts` 接口/解析变更 | `05-API文档/外部数据接口.md` | URL、参数、响应路径 |
| `src/services/stock-data.ts` 类型/配置变更 | `05-API文档/数据模型.md` | 字段表、配置 schema |
| `src/components/*-webview.ts` 消息/UI 变更 | `04-技术方案/Webview方案.md` | 消息协议表 |
| `package.json` contributes 变更 | `01-需求分析/功能需求清单.md`、`06-开发规范/技术栈.md` | 命令/快捷键/配置项表 |
| `package.json` 版本号 / scripts 变更 | `06-开发规范/发布流程.md` | 版本时间线、打包步骤 |
| 数据源字段（爱问财动态列）变化 | `04-技术方案/数据服务方案.md`、`05-API文档/外部数据接口.md` | 候选键名表 |

## 4. Git 钩子提醒

安装：`bash scripts/install-hooks.sh`

- 自动备份已有 pre-commit 钩子
- 按仓库类型（本仓库为 Node.js）生成提醒规则：
  - `src/**` 变更 → 提醒检查 01/02/05 分类
  - `package.json` 变更 → 提醒检查 01/06 分类
  - 配置文件变更 → 提醒检查 04-技术方案

## 5. 月度自查清单

- [ ] 过期脚本无告警（`bash scripts/check-staleness.sh`）
- [ ] 索引覆盖率为 100%（`bash scripts/check-index-coverage.sh`）
- [ ] 新增命令/快捷键/配置项已记录（对比 `stock-ticker/package.json`）
- [ ] 技术栈版本与实际一致（对比 package.json devDependencies / engines）
- [ ] 数据源接口 URL 与参数未漂移（对比 `stock-ticker/src/services/stock-data.ts`）

## 6. 文档编写规范

### 文档头部
每份分类文档必须包含：
```markdown
# 文档标题

> 最后验证：YYYY-MM-DD

本文描述...（一句话说明文档用途）
```

### 文档尾部
每份文档末尾包含「相关文档」区块，链接到关联文档（相对路径、`.md` 结尾）。

### 其他规范
- 单份文档不超过 200 行，超过则拆分
- 用中文命名文件；分类目录使用 `NN-分类名` 格式
- `_index.md` 是单一数据源，不要在文档文件中重复元数据

## 7. 度量指标

| 指标 | 计算方式 | 目标 |
|------|----------|------|
| 文档新鲜度 | 30 天内验证的文档占比 | ≥ 80% |
| 索引覆盖率 | _index.md 引用数 / 总 .md 文件数 | 100% |
| 链接有效性 | 内部链接无断链 | 100% |
| 配置项同步 | package.json 配置项 / 功能需求清单配置表 | 100% |
